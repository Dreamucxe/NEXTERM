MODIFICATION NOTICE (GPL-2.0 section 2a)

  libproot.so is NOT byte-for-byte identical to the file in that package. It
  has been modified on 2026-08-11, in exactly one way, and no compiled code was
  changed:

    Its ELF DT_NEEDED entry "libtalloc.so.2" was rewritten in place to

  libproot-static.so is that file, byte for byte.

  libproot-static-loader.so is the loader ELF that the same release embeds in
  its own .rodata (the region between the symbols _binary_loader_elf_start and
  _binary_loader_elf_end, 66832 bytes), copied out unchanged.
  sha256 51c3427b112edc70d1979b48209c41f332616758138de3be659cc79e50436450

Why they are packaged as "lib*.so": Android has mounted app-writable storage
W^X since API 29, so an app may not execute a binary it wrote itself. The one
app-owned directory that is executable is the native library directory, which
the installer fills at install time — so a binary that needs to run must ship
in the APK under lib/<abi>/ and be named lib*.so. The .so suffix is a
packaging requirement, not a claim that these are all shared libraries; the
upstream build is a static executable and the Termux build is a PIE. The
loaders are bundled for the same reason: proot normally writes its loader out
to a temporary file and executes that, which is exactly what the sandbox
refuses, so NEXTERM points PROOT_LOADER at the bundled copy. Each build is
paired only with the loader it was compiled against.

2. Shared libraries the Termux PRoot build links against
--------------------------------------------------------------------------

The Termux PRoot build in section 1a is dynamically linked, so the two
non-system libraries it needs are bundled beside it under lib/arm64-v8a/.
NEXTERM sets LD_LIBRARY_PATH to that directory when it executes PRoot, because
bionic does not search an app's native library directory automatically for an
exec'd process, and the RUNPATH compiled into these files points into Termux's
own private prefix, which does not exist on a device without Termux installed.
